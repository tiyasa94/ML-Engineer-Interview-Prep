# Part A — What Dynamic Programming Actually Is

DP applies to problems with **both** of two properties:
- **Optimal substructure**: the optimal solution to the whole problem can be built from optimal solutions to its subproblems.
- **Overlapping subproblems**: the same subproblems recur many times during a naive recursive solution — this is what distinguishes DP from plain divide-and-conquer (merge sort has optimal substructure but its subproblems never overlap; each half is entirely independent).

DP is the direct extension of Phase 0's memoization and the exact boundary flagged in Phase 3's Backtracking document: the moment overlapping subproblems appear in a recursive search, caching results (top-down DP) or building them iteratively (bottom-up DP) turns exponential search into polynomial computation.

# Part B — The Theory: Proving DP Applies, and How to Design It

## Verifying optimal substructure

Ask directly: can the optimal answer to the full problem be expressed using optimal answers to smaller versions of the same problem? If yes, that recursive relationship is the DP recurrence waiting to be written down.

## Verifying overlapping subproblems

Sketch the naive recursion tree (Phase 0's Recursion document) and check whether the same `(state)` gets computed multiple times via different call paths. Naive Fibonacci is the canonical example: `fib(n-2)` is computed once directly and once again inside the `fib(n-1)` branch — this repetition, at every level, is exactly what memoization eliminates.

## The 5-step framework for designing any DP solution

1. **Define the state** — precisely, in plain English: what does `dp[i]` represent?
2. **Define the recurrence** — how does `dp[i]` relate to smaller/previous states?
3. **Define the base case(s)** — the smallest states, answered directly, with no recursion.
4. **Define the computation order** — for bottom-up: what order guarantees every dependency is already computed when needed?
5. **Extract the final answer** — which `dp` value (or combination of values) IS the answer to the original problem?

This is not itself a named CLRS section, but every one of CLRS's worked DP examples (rod cutting, matrix chain multiplication, LCS) follows exactly this process — it is a teaching formalization of what the textbook does implicitly, worth using explicitly as a starting checklist for any unfamiliar DP problem.

## Space optimization: the recurring payoff

If `dp[i]` only depends on a small, fixed number of previous states (`dp[i-1]`, `dp[i-2]`, ...), the full O(n) array can be collapsed to O(1) rolling variables — always worth doing as a follow-up once a correct O(n)-space solution exists, and a very common "can you do this with less space" interview follow-up in this specific topic.

# Part C — The Core Patterns

### 1. Linear DP (Fibonacci-Shaped)

`dp[i]` depends on a small fixed set of earlier values.
```
dp = [0] * (n + 1)
dp[0], dp[1] = base_case_0, base_case_1
for i in range(2, n + 1):
    dp[i] = combine(dp[i-1], dp[i-2])
return dp[n]
```
**Signals:** "climbing stairs", "house robber", "number of ways to reach step n".

### 2. 0/1 Knapsack Shape (Include or Exclude Each Item, Once)

Naturally a 2D recurrence (item index x remaining capacity — full treatment in Topic 16), but the 1D space-optimized version appears often enough to name here: iterate items outer, capacity **inner in reverse**, to guarantee each item is used at most once (Part F elaborates on why the direction matters).
**Signals:** "each item used at most once", "partition into two equal-sum subsets".

### 3. Unbounded Knapsack Shape (Items May Repeat)

Same shape as Pattern 2, but capacity is iterated **forward**, allowing an item already used to be reused again later in the same pass.
**Signals:** "coin change" (minimum coins, or number of ways), "unlimited supply".

### 4. Longest Increasing Subsequence (LIS)

`dp[i]` = length of the longest increasing subsequence ENDING at index `i`: `dp[i] = 1 + max(dp[j] for j < i if arr[j] < arr[i])`, else `1`. This direct recurrence is `O(n^2)`. A genuinely different, faster approach exists: maintain a list of "smallest tail value for each achievable subsequence length," using **binary search** (Topic 5) to find where each new element belongs, achieving `O(n log n)` — a real complexity-class improvement worth being able to name as a distinct algorithm (patience sorting), not just a faster constant.

### 5. Kadane's Algorithm (Maximum Subarray Sum)

A specifically elegant, extremely frequently-asked O(n) time, O(1) space DP: `dp[i]` = best subarray sum ending exactly at `i` = `max(arr[i], dp[i-1] + arr[i])` — either start fresh at `i`, or extend the best subarray ending at `i-1`. The overall answer is the max over all `dp[i]`, not necessarily `dp[n-1]` itself (Part F).
**Signals:** "maximum subarray sum", "maximum sum contiguous subarray".

### 6. String DP Over Positions

`dp[i]` = some property of the string's first `i` characters, combining smaller prefixes.
**Signals:** "word break" (can the prefix be segmented into dictionary words), "decode ways" (how many ways to decode the prefix).

### 7. State Machine DP (Buy/Sell Stock Family)

The state includes not just a position but a small **finite machine state** (e.g. "currently holding a share" vs. "not holding") — `dp[i][holding]` tracks the best result at position `i` in each possible state, transitioning between states according to the allowed actions (buy, sell, cooldown, hold).
**Signals:** "buy and sell stock", especially with an added constraint (cooldown, transaction fee, limited transactions) — the base version, without constraints, often has a simpler direct greedy solution (Topic 15), but constrained variants need the state-machine DP structure.

# Part D — Optimization Principles

- **The headline complexity-class jump**: naive exponential recursion (`O(2^n)` or worse) -> polynomial DP (commonly `O(n)` or `O(n^2)`) — a fundamentally different kind of win than most of Phases 1-3's constant-factor or single-order-of-magnitude improvements, worth naming as a distinct category of optimization.
- **Space**: O(n) -> O(1) via rolling variables (Part B), whenever the recurrence only reaches back a fixed, small distance.
- **LIS's O(n^2) -> O(n log n)**: a genuine algorithmic upgrade via binary search, not just a tighter constant — a strong, specific example of Topic 5's generalization ("binary search on the answer"/a monotonic structure) reappearing inside a DP solution.

# Part E — Recognizing This Pattern in an Unfamiliar Problem

| Phrase in the problem | Likely pattern |
|---|---|
| "number of ways to...", "maximum/minimum ways to..." | Linear or String DP |
| "can you reach/achieve X" | Linear DP, often boolean-valued |
| **"subsequence" (not "substring"/"subarray")** | **Strong DP signal** — the direct mirror of Topic 3's "contiguous only" signal for sliding window |
| "each item used at most once" | 0/1 Knapsack shape (Pattern 2) |
| "unlimited supply", "any number of times" | Unbounded Knapsack shape (Pattern 3) |
| "buy and sell", with an added constraint | State Machine DP (Pattern 7) |

**The single most consequential cross-topic distinction in the entire syllabus**: "subsequence" (elements may be skipped, relative order preserved — DP territory) vs. "substring"/"subarray" (must be contiguous — Sliding Window/Two Pointers territory, Phase 1). Misreading this word is the most common reason a fundamentally sound instinct gets applied to the wrong topic's toolbox.

# Part F — Common Gotchas & Interview Traps

- **DP array off-by-one**: sizing `dp` as `n+1` (not `n`) to cleanly represent an "empty prefix" base case at index 0 is a very common necessary adjustment, easy to get wrong under time pressure.
- **0/1 vs. unbounded knapsack iteration direction** (Patterns 2 and 3): iterating the capacity dimension **forward** allows an item to be reused within the same pass (correct for unbounded); iterating it **backward** (in the space-optimized 1D form) prevents reuse (correct for 0/1). Getting this backward is a subtle, very common bug that produces a plausible-looking but wrong answer.
- **Kadane's: the answer is not necessarily `dp[n-1]`** — it is the **maximum over all** `dp[i]`, since the best subarray might end anywhere, not necessarily at the very last position; track a running `best` variable, don't just return the final `dp` value.
- **Assuming DP applies without checking for overlapping subproblems** (Part B) — if subproblems genuinely don't overlap, this is a divide-and-conquer problem, and building a DP table wastes memory without buying any speed.
- **Wrong or missing base cases** — a DP recurrence with a subtly wrong base case can look completely correct for larger inputs and only fail on edge cases (empty input, single element).

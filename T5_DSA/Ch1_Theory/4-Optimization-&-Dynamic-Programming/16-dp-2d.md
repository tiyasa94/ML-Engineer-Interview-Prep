# Part A — What Changes From 1-D

The state now needs **two indices**, `dp[i][j]`, typically arising from problems comparing/combining **two sequences** (two strings, two arrays) or navigating a genuine 2D grid. The same 5-step framework from Topic 13 still applies, extended to two dimensions — nothing about the underlying theory changes, only the shape of the table.

# Part B — The Canonical 2D DP: Longest Common Subsequence (LCS)

CLRS's own primary teaching example for this entire category (§15.4) — worth deriving properly, not just memorizing the recurrence.

**State**: `dp[i][j]` = length of the longest common subsequence between the first `i` characters of `s1` and the first `j` characters of `s2`.

**Recurrence, derived**:
- If `s1[i-1] == s2[j-1]` (the current characters match): this matching character **must** be part of the LCS of these two prefixes — proof by exchange: if some LCS of the two prefixes did *not* use this matched pair, appending it would extend that LCS by one, contradicting its assumed maximality unless it was already using an equally-good pairing. So `dp[i][j] = dp[i-1][j-1] + 1`.
- If they don't match: the LCS excludes at least one of the two current characters — try excluding each in turn and take the best: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

```
dp = [[0] * (len(s2)+1) for _ in range(len(s1)+1)]
for i in range(1, len(s1)+1):
    for j in range(1, len(s2)+1):
        if s1[i-1] == s2[j-1]:
            dp[i][j] = dp[i-1][j-1] + 1
        else:
            dp[i][j] = max(dp[i-1][j], dp[i][j-1])
return dp[-1][-1]
```

This exact derivation pattern — "does the last element of each sequence participate in the optimal answer, and what follows if it does or doesn't" — is the template nearly every two-string DP problem below reuses.

# Part C — The Core Patterns

### 1. Two-String Comparison DP

- **LCS** (Part B) — subsequence, not necessarily contiguous.
- **Edit Distance**: `dp[i][j]` = minimum operations (insert, delete, replace) to transform the first `i` characters of `s1` into the first `j` characters of `s2`. A direct extension of LCS's structure with a 3-way choice on mismatch instead of 2-way: `dp[i][j] = min(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1]+cost)`, where `cost` is 0 if the characters match, 1 if replacing.
- **Longest Common SUBSTRING** (distinct from subsequence — Part F elaborates): the recurrence **resets to 0 on any mismatch** instead of taking a `max`, since contiguity is required.
**Signals:** "two strings", "common subsequence/substring", "edit distance", "convert one string to another".

### 2. Grid Path DP

`dp[i][j]` = best value reaching cell `(i,j)`, depending only on `dp[i-1][j]` and `dp[i][j-1]` (arriving from above or from the left) for a right/down-only movement grid.
**Signals:** "grid", "paths", "ways to reach", "minimum/maximum path sum", "obstacles".

### 3. 0/1 Knapsack, in Its Natural 2D Form

`dp[i][capacity]` = best achievable value using the first `i` items within the given capacity — the natural, un-optimized form of Topic 13's space-optimized 1D version. Deriving the 2D version first, then space-optimizing to 1D afterward (Part D), is the recommended order — get the recurrence right with the full table before compressing it.
**Signals:** "items with weight/value", "capacity constraint", "partition into equal-sum subsets" (revisit Topic 13, now through the full 2D lens before optimizing).

### 4. Interval DP

`dp[i][j]` represents the best answer for the **subrange** `[i, j]`, filled by increasing range length — this is a structurally different iteration order from every other pattern here (Part F). CLRS's Matrix Chain Multiplication (§15.2) is the canonical example: `dp[i][j]` = minimum multiplication cost to compute the product of matrices `i` through `j`, trying every possible split point `k` in between. Longest Palindromic Substring/Subsequence also fit this shape (`dp[i][j]` = best answer for the substring/subsequence spanning `i` to `j`).
**Signals:** "optimal way to combine/split a range", "palindromic substring/subsequence", matrix-chain-shaped cost-minimization problems.

# Part D — Optimization Principles

- **Time**: `O(n*m)` is typically the target, and often genuinely optimal for two-sequence comparison problems — there is usually no way to avoid examining every pair of prefixes without additional problem-specific structure.
- **Space**: `O(n*m)` -> `O(min(n,m))` via a **rolling-row** technique, since `dp[i][j]` (in patterns 1-3) typically depends only on the *previous* row and the current row being built — a concrete, frequently-asked follow-up optimization, the direct 2D analog of Topic 13's rolling-variable technique.
- **Sequencing matters**: get the full 2D table correct first, *then* optimize space — attempting to space-optimize before the recurrence itself is verified correct is a common source of compounded bugs (the same discipline as Topic 13's overall philosophy, doubled in a 2D table's added complexity).

# Part F — Common Gotchas & Interview Traps

- **2D off-by-one**: needing `(n+1) x (m+1)` tables (not `n x m`) to cleanly represent empty-prefix base cases at row/column 0 — Topic 13's 1D off-by-one gotcha, doubled.
- **Confusing longest common SUBSEQUENCE with longest common SUBSTRING** (Part C.1) — subsequence's recurrence takes a `max` on mismatch (allowing a gap); substring's recurrence **resets to 0** on mismatch (contiguity required, so a break anywhere ends that particular run entirely). This is a very common, very consequential mixup.
- **Interval DP's iteration order**: must process subranges by **increasing length**, not naive row-by-row or column-by-column order — `dp[i][j]` for a longer range depends on `dp` values for every shorter range strictly contained within it, so a naive iteration order can read uninitialized/incorrect values. This is a genuinely distinct gotcha from every other pattern in this document, worth flagging on its own.
- **Space-optimizing before verifying correctness** — get the full, correct 2D table working first; compress to rolling rows only afterward (Part D).
